# Deploying TechnoCool Inventory on Coolify (Contabo VPS)

The whole system is one Coolify resource built from [`docker-compose.coolify.yml`](../docker-compose.coolify.yml):

| Service | What it is | Reachable from outside |
|---|---|---|
| `app` | Web app + `/api/v1` (Next.js, port 3000). Runs database migrations and the seed on every start. | Yes, through Coolify's proxy (HTTPS) |
| `worker` | Background jobs: Excel imports, PDFs, emails, phone push, low-stock digest, scheduled reports | No |
| `postgres` | PostgreSQL 16 | No |
| `redis` | Redis 7 (password, AOF persistence) | No |
| `minio` | Private S3-compatible storage for product photos, documents and import files | No |
| `backup` | Nightly database dump + copy of the stored files | No |

`app` and `worker` are built from the same `docker/Dockerfile`. No service publishes a host port; only the app is reachable, and only through the domain you give it. Database, Redis and storage passwords and the JWT secrets are generated by Coolify the first time you load the compose file.

## 0. Before you start

- **Server:** the Contabo VPS is added in Coolify (*Servers*) and shows as reachable. Building the image needs memory: 4 GB RAM or more is comfortable. On a smaller VPS add swap first (`fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`, plus a line in `/etc/fstab`).
- **DNS:** an `A` record for the domain you will use (e.g. `inventory.your-domain.com`) pointing to the VPS's IP address. Ports 80 and 443 open on the server (Coolify's proxy uses them for HTTPS certificates).
- **Repository:** Coolify can read the Git repository (GitHub App, or a deploy key for a private repo).

## 1. Create the resource

1. Coolify → your project → **+ New → Application** → pick the repository (private repo: *Private Repository (with GitHub App)* or *with Deploy Key*), branch `main`.
2. **Build pack: Docker Compose.** **Docker Compose location:** `/docker-compose.coolify.yml`. Base directory `/`.
3. Coolify reads the file and lists the services. Under **Domains for app** enter:

   ```
   https://inventory.your-domain.com:3000
   ```

   `:3000` tells the proxy which container port to send traffic to; people still open `https://inventory.your-domain.com` (no port). Leave every other service without a domain.

## 2. Environment variables

Open **Environment Variables**. The `SERVICE_*` ones are already filled in (generated passwords and secrets): leave them. Fill in:

| Variable | Required | Value |
|---|---|---|
| `APP_URL` | yes | The public address, exactly as users open it: `https://inventory.your-domain.com` (no port, no trailing slash). A mismatch makes every save fail with a 403 (CSRF check). |
| `ADMIN_PASSWORD` | yes | Password for the first admin account. Used only when the account is created; change it later in the app. |
| `ADMIN_USERNAME` | no | Default `admin` |
| `COMPANY_NAME` | no | Printed on GRNs, challans and invoices. Default `Techno Cool Associates` |
| `SEED_SAMPLE_DATA` | no | Default `false` (start with empty suppliers, customers and projects). `true` loads demo data. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | no | Email. Leave `SMTP_HOST` empty to run without email (in-app notifications still work). Gmail: `smtp.gmail.com`, `465`, `true`, your address, a 16-letter app password, `TechnoCool Inventory <same address>`. |
| `FCM_SERVICE_ACCOUNT` | no | Firebase service-account key for phone push (JSON, or `base64 -w0 key.json`). Empty = push off. |
| `TRUSTED_ORIGINS` | no | Extra web addresses for the same app, comma-separated (e.g. a `www.` variant) |
| `BACKUP_TIME` / `BACKUP_KEEP_DAYS` | no | Nightly backup time (Asia/Dhaka) and how many days to keep. Default `02:30` / `14` |
| `LOG_LEVEL` | no | Default `info` |

Mark `ADMIN_PASSWORD`, `SMTP_PASSWORD` and `FCM_SERVICE_ACCOUNT` as secrets (lock icon). The compose file passes each variable to the services that need it (SMTP and FCM go to both app and worker).

## 3. Deploy

Click **Deploy**. The first build takes several minutes. Start-up order is handled by the compose file:

1. `postgres`, `redis`, `minio` start and become healthy.
2. `app` runs `prisma migrate deploy`, then the idempotent seed (roles, warehouses, admin user…), then starts the server. Its health check is `GET /api/v1/health` (checks the database and Redis).
3. `worker` starts once the app is healthy (so migrations are done). Its log shows `worker started`.

If a migration fails, the app container stops and the log shows why.

Then open `https://inventory.your-domain.com/login`, sign in with `ADMIN_USERNAME` / `ADMIN_PASSWORD`, set a new admin password, and create users under **Users & roles**.

## 4. Updating

Push to `main`, then **Redeploy** in Coolify (or turn on *Automatic deployment* / the GitHub webhook in the resource's settings). Migrations run automatically on every start. Data lives in Docker volumes (`pgdata`, `redisdata`, `miniodata`, `backups`), which survive redeploys.

Don't change `SERVICE_PASSWORD_POSTGRES` / `SERVICE_USER_POSTGRES` / `SERVICE_*_MINIO` after the first deploy: the database and storage were created with them. Changing a `SERVICE_PASSWORD_64_JWT*` secret signs everyone out (they log in again).

After changing environment variables, redeploy (the app and the worker both read them only at start).

## 5. Backups

The `backup` service writes, every night at `BACKUP_TIME`:

- `db-YYYY-MM-DD_HHMM.dump`: the whole database (`pg_dump` custom format)
- `files-YYYY-MM-DD_HHMM.tar.gz`: everything in storage (photos, documents, import files)

They are kept `BACKUP_KEEP_DAYS` days in the `backups` volume. **That volume is on the same server**, so also copy them somewhere else. On the VPS (SSH):

```bash
docker volume ls | grep backups                 # e.g. abc123xyz_backups
ls -lh /var/lib/docker/volumes/abc123xyz_backups/_data
```

and from your PC: `scp root@<vps-ip>:/var/lib/docker/volumes/abc123xyz_backups/_data/db-*.dump .` (or set up `rclone` on the VPS to copy that folder nightly to Google Drive or Contabo Object Storage).

Backup now, without waiting for the night: Coolify → the resource → `backup` container → **Terminal** (or `docker exec -it <backup container> sh` on the VPS) and run `pg_dump -Fc -f /backups/db-manual.dump`.

**Restoring the database** (on the VPS; stop `app` and `worker` first so nothing writes):

```bash
docker ps --format '{{.Names}}' | grep -E 'postgres|backup'    # find the container names
docker exec <backup container> pg_restore --clean --if-exists --no-owner -d stockbook /backups/db-2026-11-08_0230.dump
```

**Restoring the files:**

```bash
docker run --rm -v abc123xyz_miniodata:/data -v abc123xyz_backups:/backups:ro alpine \
  sh -c 'rm -rf /data/* /data/.minio.sys && tar -xzf /backups/files-2026-11-08_0230.tar.gz -C /data && chown -R 1001:1001 /data'
```

Then start `app` and `worker` again.

## 6. Notes

- **HTTPS / proxy:** Coolify's proxy terminates TLS. The compose file sets `TRUST_PROXY=true` (client IPs and host from `X-Forwarded-*`) and `COOKIE_SECURE=true` (cookies only over HTTPS), both required behind the proxy.
- **PDFs:** the image includes Chromium and fonts; the worker renders GRNs, challans and invoices with it. Nothing else to install.
- **Swagger UI** (`/api/docs`) loads its assets from cdn.jsdelivr.net. Every protected API call still needs a token.
- **Mobile apps** use `https://inventory.your-domain.com/api/v1` with bearer tokens.
- **Outside storage instead of MinIO (optional):** to keep files in Contabo Object Storage (or any S3 service), create a **private** bucket and an access key, and in `docker-compose.coolify.yml` change the `S3_*` lines of both `app` and `worker` to `S3_ENDPOINT=https://eu2.contabostorage.com`, `S3_REGION=default`, `S3_BUCKET=<bucket>`, `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` (as variables), `S3_AUTO_CREATE_BUCKET=false`. The `minio` service can then be removed (and the `miniodata` mount from `backup`).

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Browser shows **No Available Server** | The app's domain is missing `:3000`, or the app isn't healthy yet (check its logs). |
| Login works but every save fails with **403** | `APP_URL` doesn't match the address in the browser (`https` vs `http`, `www.` or not). Fix it and redeploy, or add the other address to `TRUSTED_ORIGINS`. |
| Can't stay logged in | The site isn't opened over HTTPS (`COOKIE_SECURE=true` needs it). |
| Build is killed / fails with out-of-memory | Add swap or more RAM (section 0). |
| PDFs / emails / imports never finish | The worker isn't running: check its logs for `worker started` and for environment errors. |
| `Invalid environment configuration` in a log | The listed variable is missing or malformed; fix it in Coolify and redeploy. |
| No emails | `SMTP_HOST` empty (emails logged as SKIPPED in the app), wrong credentials (the worker log shows the SMTP error), or the user has no email address / turned that notification's email off. |
